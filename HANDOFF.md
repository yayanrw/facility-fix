The full three-account flow was walked in the browser: asset submission → reject with formatted remarks → revise → resubmit → approve → approve → facility appears in the master, then a damage report against it with the deadline changed to 3 days.

**Next**: Roadmap step 7 — `lib/email.ts`, `app/api/cron/deadline/route.ts`, and the cron entry in `vercel.ts`. Logic and the recipient rules are already specified in `docs/04-notifications.md`.

**Watch out**: Resend is still blocked on you accepting its marketplace terms at https://vercel.com/yayanrws-projects/~/integrations/accept-terms/resend?source=cli — step 7 needs it. The database currently holds verification data, not a real seed: three users (`req@`, `rev@`, `app@ff.test`, password `FlowTest!2026`), one published facility, two submissions; step 8 replaces this. Two rules that are easy to break by accident: workflow functions must stay `security invoker` with `execute` granted only to `service_role` (a `security definer` function in `public` is callable by anyone holding the anon key), and RLS policies must wrap auth calls as `(select auth.uid())` or the advisors flag a per-row re-evaluation. Since 2026-05-30 new tables in the `public` schema are no longer auto-exposed to the Data API, so any table added later needs that checked explicitly.
